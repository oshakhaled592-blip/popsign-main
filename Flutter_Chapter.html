7.1 Introduction to Flutter and Dart

1. What is Flutter?

Flutter is an open-source UI software development toolkit created by Google. It is used for building natively compiled applications for mobile (Android and iOS), web, desktop, and even embedded devices, all from a single codebase. Launched officially in 2017, Flutter quickly gained popularity due to its performance, flexibility, and developer-friendly architecture.

Key Features of Flutter:

  • Cross-Platform Development: Write your code once and run it anywhere. No need to maintain separate codebases for Android, iOS, Web, or Desktop.
  • Native Performance: Flutter compiles down to native ARM code using Dart, which ensures smooth performance, unlike other hybrid frameworks that rely on JavaScript bridges.
  • Beautiful UI: Flutter provides a rich set of widgets that mimic the behavior of native components. Developers can easily build beautiful and custom user interfaces.
  • Hot Reload: This allows developers to instantly see the changes in the UI without restarting the app, significantly speeding up the development process.
  • Custom Rendering Engine: Flutter uses its own rendering engine (Skia/Impeller) which means the UI looks and behaves consistently across all platforms.

2. Understanding Dart: The Language Behind Flutter

Dart is the programming language used to build Flutter applications. It is also developed by Google and was designed specifically to create fast, modern, reactive apps.

Why Dart?

  • Optimized for UI: Dart is built to handle UI development. It allows for layout expressions, smooth animations, and declarative programming.
  • Object-Oriented and Class-Based: Dart follows modern programming principles with strong support for classes, inheritance, and interfaces.
  • Ahead-of-Time (AOT) & Just-in-Time (JIT) Compilation: AOT compiles the code ahead of time for fast startup and better performance in production. JIT allows for hot reload during development, improving developer efficiency.
  • Strongly Typed with Null Safety: Prevents null reference errors at compile time, improving application stability.
  • Garbage Collected and Memory Safe: It helps manage resources efficiently and prevents many common memory issues.

3. The Relationship Between Flutter and Dart

Flutter and Dart are designed to work hand-in-hand. Dart powers the logic and behavior, while Flutter provides the UI framework built entirely with Dart.

  • Single Language Stack: Unlike other frameworks (like React Native, which uses JavaScript with some native code), Flutter allows the entire application to be written in Dart. This simplifies development and debugging.
  • No Need for OEM Widgets: Flutter draws the UI components itself using Dart and Skia, rather than relying on the platform's native components. This ensures uniform appearance and behavior.
  • Customizability: Because everything in Flutter is a widget, including layout elements, animations, and even themes, developers have full control over the appearance and functionality.

4. Flutter Architecture Overview

Flutter follows a layered architecture consisting of:

  • Framework Layer: The top layer, written in Dart, includes the core libraries, rendering system, widgets, and foundation classes.
  • Engine Layer: Written in C++, the engine uses Skia/Impeller to render everything and handles input, text layout, and more.
  • Embedder Layer: Platform-specific code that allows Flutter to run on various platforms like Android, iOS, web, etc.

5. Advantages of Choosing Flutter for I Hear You

The I Hear You application targets sign language learners on both Android and iOS. Flutter was selected because:

  • A single codebase covers both platforms simultaneously, reducing development time and cost.
  • The rich widget ecosystem supports complex UI interactions like flashcard animations and video playback.
  • The flutter_screenutil package ensures fully responsive layouts across all screen sizes.
  • Firebase integration is first-class with official Flutter packages.
  • Hot Reload enabled fast iteration during development.

6. Challenges and Considerations

  • App Size: Flutter apps can be slightly larger in size due to the built-in rendering engine.
  • Limited Native SDK Access: Although Flutter supports platform channels, working with native APIs still requires writing native platform-specific code in Kotlin/Swift.
  • Learning Curve: Dart is not as widely known as JavaScript or Kotlin, requiring an initial learning investment.

7. Summary

Flutter and Dart together provide a robust ecosystem for building modern, responsive, and high-performance applications across multiple platforms. Their integration creates a development experience that is both productive and powerful, with the ability to produce beautiful UIs and maintain a single codebase. This is precisely why Flutter was chosen for the I Hear You sign-language learning application.

3. What is State Management in Flutter?

In Flutter, everything is a widget. These widgets can be stateless (don't change) or stateful (change over time). Managing the changes in these widgets — especially when the UI depends on data from API responses or user actions — is referred to as State Management.

Flutter offers several approaches:

  • setState — for local widget state
  • ValueNotifier — for lightweight global reactive state
  • ChangeNotifier — for feature-specific complex state
  • SharedPreferences — for persistent state across sessions
  • Provider, Bloc/Cubit, Riverpod, GetX — for larger apps

For the I Hear You application, a lightweight, pragmatic approach was chosen — using ValueNotifier, ChangeNotifier, SharedPreferences, and setState — without heavy global state libraries, keeping the codebase lean and maintainable.

4. Understanding ValueNotifier and State

A ValueNotifier<T> is a class that holds a single value and notifies all registered listeners whenever that value changes. It is Flutter's simplest built-in reactive primitive.

4.1 Theme Notifier — Dark / Light Mode

A global ValueNotifier<ThemeMode> manages dark/light mode for the entire app:

// theme_notifier.dart
final themeNotifier = ValueNotifier<ThemeMode>(ThemeMode.dark);

Used in main.dart to rebuild the entire MaterialApp when the user toggles the theme:

ValueListenableBuilder<ThemeMode>(
  valueListenable: themeNotifier,
  builder: (context, mode, _) => MaterialApp(
    themeMode: mode,
    theme: ThemeData.light(),
    darkTheme: ThemeData.dark(),
    onGenerateRoute: AppRouter.generateRoute,
  ),
)

The theme choice is persisted to SharedPreferences (key: isDark) and loaded before runApp() in main.dart so the splash screen always shows the correct theme immediately — eliminating the flash-of-wrong-theme problem:

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
  final prefs = await SharedPreferences.getInstance();
  final savedDark = prefs.getBool('isDark');
  if (savedDark != null) {
    themeNotifier.value = savedDark ? ThemeMode.dark : ThemeMode.light;
  }
  runApp(const IHeartYouApp());
}

5. ChangeNotifier — Translation Feature State

For the sign-language translation feature, a TranslationNotifier extending ChangeNotifier manages the full lifecycle of a video prediction request:

enum TranslationStatus { idle, loading, success, error }
enum ServerStatus { unknown, online, offline }

class TranslationNotifier extends ChangeNotifier {
  final _service = TranslationService();
  bool _disposed = false;

  @override
  void dispose() {
    _disposed = true;
    super.dispose();
  }

  void _notify() {
    if (!_disposed) notifyListeners();
  }

  TranslationStatus _status = TranslationStatus.idle;
  PredictionResult? _result;
  String _error = '';
  final List<PredictionItem> _sentence = [];

  bool get isLoading => _status == TranslationStatus.loading;
  bool get isSuccess => _status == TranslationStatus.success;
  bool get isError   => _status == TranslationStatus.error;

  Future<void> predict(File video) async {
    _status = TranslationStatus.loading;
    _result = null;
    _error = '';
    _notify();

    try {
      _result = await _service.predict(video);
      _status = TranslationStatus.success;
      _sentence.add(_result!.top);
    } catch (e) {
      _error = e.toString().replaceFirst('Exception: ', '');
      _status = TranslationStatus.error;
    }
    _notify();
  }
}

The _disposed flag is a critical safety pattern: it prevents notifyListeners() from being called after the widget is removed from the tree — protecting against the common ChangeNotifier.debugAssertNotDisposed crash when async operations outlive their widget.

8. Benefits of This State Management Approach

  • Simple and Clean Syntax: No boilerplate event classes or code generation required.
  • Testable: Service classes and notifiers are easy to unit test in isolation.
  • Scalable: The approach scales well for small-to-medium apps without overwhelming complexity.
  • Separation of Concerns: Keeps UI code (screens) separate from business logic (services) and persistence (SharedPreferences).

9. Summary

The I Hear You app uses a four-layer state management model: ValueNotifier for global reactive app state (theme and language), ChangeNotifier for feature-specific complex state (translation), SharedPreferences for persistent cross-session data, and setState for transient screen-level state. This combination provides reactivity where needed without adding unnecessary overhead.

}

7.4 API Integration using HTTP in Flutter

1. Introduction

Modern mobile apps rarely operate in isolation; they communicate with remote servers through RESTful APIs to fetch or send data. In Flutter, this is typically done using the http package — the standard Dart HTTP client — or the more advanced dio package.

The I Hear You application integrates three external servers:

  • A backend REST API at http://91.108.113.135 — primary authentication source
  • A Firebase Auth server — for password management operations
  • A dedicated AI server — for sign-language prediction and conversational chat

All external communication is abstracted into service classes (AuthService, TranslationService, ChatService), keeping UI code free of HTTP concerns.

2. Using the http Package

The http package is Flutter's standard HTTP client for making REST API calls.

2.2 The AuthService Pattern

Every method in AuthService returns an AuthResult with a success flag and a user-facing message, keeping error handling uniform across the app:

class AuthResult {
  final bool success;
  final String message;
  AuthResult({required this.success, required this.message});
}

class AuthService {
  static const _base = 'http://91.108.113.135';
  static const _timeout = Duration(seconds: 20);
  final _fb = FirebaseAuth.instance;
}

2.3 Making a POST Request — Login

Future<AuthResult> login({
  required String email,
  required String password,
}) async {
  try {
    final res = await http.post(
      Uri.parse('$_base/api/auth/login'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode({'email': email, 'password': password}),
    ).timeout(_timeout);

    final json = _decode(res);

    // Save token early — present even in verify-required responses
    final token = _extractToken(json);
    if (token != null) {
      final prefs = await SharedPreferences.getInstance();
      await prefs.setString('authToken', token);
      await prefs.setString('userEmail', email);
    }

    if (json['success'] != true) {
      return AuthResult(
        success: false,
        message: json['message']?.toString() ?? 'Login failed',
      );
    }

    // Mirror into Firebase for password-management operations
    await _signIntoFirebase(email, password);

    return AuthResult(success: true, message: json['message'] ?? 'Logged in');
  } catch (_) {
    return AuthResult(
      success: false,
      message: 'Network error. Check your internet connection',
    );
  }
}

2.4 Making a POST Request — Signup

Future<AuthResult> signup({
  required String email,
  required String password,
}) async {
  try {
    final res = await http.post(
      Uri.parse('$_base/api/auth/signup'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode({'email': email, 'password': password}),
    ).timeout(_timeout);

    final json = _decode(res);
    final ok = json['success'] == true;

    if (ok) {
      try {
        await _fb.createUserWithEmailAndPassword(email: email, password: password);
      } catch (_) {}
    }

    return AuthResult(
      success: ok,
      message: json['message']?.toString() ?? 'Something went wrong',
    );
  } catch (_) {
    return AuthResult(success: false, message: 'Network error.');
  }
}

2.5 Response Parsing Helper

Map<String, dynamic> _decode(http.Response res) {
  try {
    final decoded = jsonDecode(res.body);
    if (decoded is Map<String, dynamic>) return decoded;
  } catch (_) {}
  return {};
}

String? _extractToken(Map<String, dynamic> json) {
  for (final key in ['token', 'access_token', 'accessToken', 'jwt']) {
    final v = json[key];
    if (v is String && v.isNotEmpty) return v;
  }
  // Also check nested 'data' and 'user' objects
  final data = json['data'];
  if (data is Map<String, dynamic>) {
    final nested = _extractToken(data);
    if (nested != null) return nested;
  }
  return null;
}

4. Firebase Auth Integration

Firebase Auth is integrated as a secondary auth layer for password-management operations. During login the app also signs into Firebase so that password-change operations can be performed later:

Future<void> _signIntoFirebase(String email, String password) async {
  try {
    await _fb.signInWithEmailAndPassword(email: email, password: password);
  } on FirebaseAuthException catch (e) {
    if (e.code == 'user-not-found') {
      try {
        await _fb.createUserWithEmailAndPassword(email: email, password: password);
      } catch (_) {}
    }
    // Other errors are non-fatal — backend is the primary auth source
  }
}

// Firebase error mapping
String _fbError(FirebaseAuthException e) {
  switch (e.code) {
    case 'wrong-password':
    case 'invalid-credential':    return 'Current password is incorrect.';
    case 'user-not-found':        return 'No account found for this email.';
    case 'weak-password':         return 'New password is too weak (min 6 characters).';
    case 'requires-recent-login': return 'Please log out and log in again, then retry.';
    case 'too-many-requests':     return 'Too many attempts. Please try again later.';
    default:                      return e.message ?? 'An error occurred.';
  }
}

6. Translation Service — Multipart File Upload

The sign-language translation feature sends a video file to the AI server using http.MultipartRequest:

class TranslationService {
  final _base = 'http://91.108.113.135';

  Future<bool> checkHealth() async {
    final res = await http.get(Uri.parse('$_base/health'))
        .timeout(const Duration(seconds: 10));
    return res.statusCode == 200;
  }

  Future<List<String>> getClasses() async {
    final res = await http.get(Uri.parse('$_base/classes'))
        .timeout(const Duration(seconds: 15));
    final json = jsonDecode(res.body);
    return List<String>.from(json['classes'] ?? []);
  }

  Future<PredictionResult> predict(File videoFile) async {
    final request = http.MultipartRequest(
      'POST',
      Uri.parse('$_base/predict'),
    );
    request.files.add(
      await http.MultipartFile.fromPath('video', videoFile.path),
    );
    final streamed = await request.send().timeout(const Duration(seconds: 60));
    final res = await http.Response.fromStream(streamed);
    if (res.statusCode != 200) throw Exception('Prediction failed');
    return PredictionResult.fromJson(jsonDecode(res.body));
  }
}

7. Chat Service — Session-Based Messaging

class ChatService {
  final _base = 'http://91.108.113.135';

  Future<String> newSession() async {
    final res = await http.post(
      Uri.parse('$_base/session/new'),
      headers: {'Content-Type': 'application/json'},
    ).timeout(const Duration(seconds: 15));
    return jsonDecode(res.body)['session_id'];
  }

  Future<String> sendMessage({
    required String sessionId,
    required String message,
  }) async {
    final res = await http.post(
      Uri.parse('$_base/chat'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode({'session_id': sessionId, 'message': message}),
    ).timeout(const Duration(seconds: 30));
    return jsonDecode(res.body)['response'];
  }
}

  • try/catch blocks — to catch network errors, JSON decode failures, and timeouts
  • Uniform AuthResult / Exception return — so UI code always knows how to handle any outcome
try {

  if (!knownWords.contains(word)) {
    knownWords.add(word);
    await prefs.setStringList('known_$_level', knownWords);

  setState(() => _currentIndex++);
